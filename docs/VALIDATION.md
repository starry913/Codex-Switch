# 验证记录

## 本机只读诊断

- Windows CLI：0.154.0。
- Windows VS Code 插件：openai.chatgpt-26.908.40401-win32-x64。
- 当前 Windows 配置使用自定义 RightCode 服务和本机代理，文件型 API Key。
- Windows 会话索引包含多个历史服务标记，说明保留所有原始记录是必要条件；该现象本身不证明客户端过滤规则。
- Ubuntu-22.04 有独立 Codex 数据目录。其 PATH 中的 Codex 启动脚本位于 Windows 挂载路径，需要在真实服务验收时确认实际使用的执行程序。
- 本次开发没有更换真实服务、导入真实凭据到工具保险库或修改真实会话和记忆。

## 自动化验证范围

所有写入测试仅使用临时 Codex 目录、虚拟凭据和虚拟历史。验证文件级完整性、事务恢复和跨环境隔离，不能替代服务商协议及真实客户端验收。

## 真实客户端验收清单（待用户完成初次配置后执行）

每个实际使用的环境和入口分别验证：

1. 保存当前连接，添加另外两个服务；账号 Key 不进入报告。
2. 记录测试项目路径、一个旧会话 ID、一个可明确验证的项目记忆事实。
3. 退出相关客户端后切换服务，重新打开同一入口。
4. 核对实际连接目标、旧会话可见性、项目路径、续聊、记忆读取。
5. 分别验证三个服务，并切回原连接。
6. 检查配置、凭据与目标服务匹配，项目文件和原有数据仍可访问。

如果续聊失败，记录客户端版本、服务名、脱敏错误码和失败阶段。不要用“文件未丢失”代替“记忆已加载”的结论。
